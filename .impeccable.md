# Impeccable

## Design Context

### Users

Developers reviewing pull requests, branches, and working-tree changes on their own machine.
They live in GitHub's PR UI all day; prreview is a localhost stand-in for that surface, used in
long focused review sessions in a code editor context (dark theme).

### Brand Personality

Native, dense, unobtrusive. The tool should feel like a first-party GitHub page, not a themed
third-party app. Nothing should draw attention to itself except the review content: diffs,
findings, explanations.

### Aesthetic Direction

GitHub Primer is the design system, verbatim: Mona Sans, Primer color/spacing/radius tokens,
octicons. Dark theme is the primary target. Anti-reference: anything that reads as a custom
design language layered over Primer (oversized pills, decorative boxes, floating controls).

### Design Principles

- Match GitHub's own rendering of the same concept: labels look like issue labels (small,
  single-line, ellipsis — never a wrapping box), file lists look like PR file trees, chrome
  buttons are quiet and squarish.
- Controls belong to a layout region; nothing floats over scrollable content or scrollbars.
- One element per concept across states: a control that survives a state change (fold/unfold)
  is the same element, same style, animated in place — never a swapped twin.
- Density over air: this is a work tool; prefer GitHub-PR-page density to generous padding.
- Motion is Primer-quiet: short fades and slides on state changes, `--motion-*` tokens,
  reduced-motion respected. No bounce, no decoration.
